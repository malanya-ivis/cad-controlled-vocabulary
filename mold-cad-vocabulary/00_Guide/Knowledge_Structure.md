# 金型CADの知識構造

このノートは、集めた資料から「形状をどう見分け、どう記述するか」を整理する入口です。分類と記述ルールは本プロジェクトの案です。用語の定義を確認する資料は、各概念ノートの Supporting sources にあります。

## 形状 → 性質 → 関係 → 部品の記述

| 整理する内容 | 入口 | 具体例 |
|---|---|---|
| 部品のどこに、どんな形があるか | [[Shape_Features|形状の特徴]] | 穴の入口に座ぐりがある。ポケットの角にフィレットがある。 |
| その形にどんな値・条件があるか | [[Shape_Properties|形状の性質]] | 抜き方向は +Z、角度は 2°。壁の厚さは場所によって違う。 |
| 内部がどうなっているか | [[Internal_Structures|内部と流路]] | 内部の空洞が開口部につながる。冷却の目的は設計資料で確認する。 |
| 特徴同士がどうつながるか | [[Feature_Relations|特徴の関係]] | 穴と座ぐりは同じ軸を持つ。二つの流路が内部で交わる。 |
| 一つの部品をどう記録するか | [[Single_Part_Description_Example|部品の記述例]] | 特徴のID、位置、寸法、関係、根拠を一緒に記録する。 |

実際の STL を使った適用例は [[Simple_CAD_Dataset_Study]] にあります。21件の外形記録と、座ぐり・皿ざぐり・ポケット・交差リブの四つの部品記述を確認できます。

[[Knowledge_Structure.canvas]] を開くと、分類から概念、部品の記述例までを一枚の図で確認できます。分類の箱は整理用です。すべての線が上位・下位の関係を表すわけではありません。

## 関係を言葉で残す

単にリンクを付けるだけでは、関係の意味が分かりません。例えば、概念の説明では「Counterbore は Hole の入口形状」と書きます。実際の部品では「F-02 の座ぐりと F-01 の穴は同じ軸」と書きます。概念と部品上の特徴を分け、関係名と対象を記録します。

Obsidian の Graph View はノートのつながりを表示します。関係の種類は線に表示されないため、[[Feature_Relations]] と各概念ノートの表で確認します。Sources を含めずに知識を見たい場合の検索例：

```text
path:"35_Knowledge_Structure" OR (path:"30_Concepts" [scope_role:core]) OR path:"45_Part_Examples"
```

## 課題3へのつながり

概念には concept_id、意味、説明に必要な項目を記録します。部品上の特徴には feature_id、概念のID、位置、属性、関係、根拠を記録します。この形なら、後でデータベースに移し、「座ぐり付きの穴」や「冷却流路につながる穴」を検索するための項目が分かります。

RAGでは、用語の説明を探すための文章と、部品上の特徴を検索するための記録を使います。文章だけで寸法や接続を判断せず、記録された値・関係・根拠を合わせて参照する設計が必要です。ここで作るノートはその準備であり、CAD検索システムの実装はまだ行っていません。

データ項目を考える際は、[[CAD_Geometry_Representation_and_Evidence]]も参照します。形状の概念、STLやSTEPで観察できる幾何、図面・3Dモデルに書かれた公差や粗さの要求は、別の記録として扱う案です。

## 複雑な部品での確認

[[Final_Selected_Dataset_Study]] は93件の外観と、四件の詳しい記述を整理しています。[[Shape_Comparison_Examples]] では、似た形を断面で比べます。段付きの貫通長穴、底が一部残る凹部、開口した内部空間、接続が未確認の穴の例があります。既存の概念IDを使い、違いは属性として保存しています。
